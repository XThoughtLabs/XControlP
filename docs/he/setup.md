## 1. התקנה והפעלה ראשונה

1. מתקינים Python 3.10 ומעלה מ-[python.org](https://www.python.org/downloads/) (משאירים את האפשרות שמתקינה את `py`).
2. שמים את XControlP בתיקייה משלכם, למשל `C:\Users\<you>\XControlP` (`git clone` או **Download ZIP**).
3. לוחצים פעמיים על `create_shortcut.pyw`: הוא יוצר על שולחן העבודה קיצור דרך **XControlP**. אם זה לא הצליח, הסיבה תיכתב ב-`shortcut-error.txt`.
4. פותחים את קיצור הדרך.

מה קורה בהפעלה:

- אם אין `projects.json`, הוא נוצר מתוך `templates/projects.example.json` (לוח ריק). קובץ `projects.json` קיים לעולם לא נדרס.
- התוכנה בונה מהקבצים שלכם את `data.js` (אותו קורא החלון) ומפעילה שרת אינטרנט קטן שרק המחשב הזה יכול להגיע אליו (`127.0.0.1`). בקשות מתקבלות רק מחלון הלוח, לפי מפתח שניתן בהפעלה.
- החלון נפתח כחלון-אפליקציה של Edge. התוכנה נסגרת בעצמה כ-10 דקות אחרי שהחלון נסגר.
- סנכרון רץ פעם אחת (ראו [סעיף 4](#4-התקדמות-שמתעדכנת-מעצמה)).

כל עוד החלון פתוח, התוכנה בונה מחדש את `data.js` ברגע ש-`projects.json` או קובץ נתונים אחר משתנה, והחלון קורא אותו שוב כל 20 שניות. אחרי עריכה לא צריך להפעיל שום דבר מחדש.

לבנות את `data.js` בלי לפתוח חלון: `python XControlP.pyw --build`.

## 3. projects.json: קבוצות, פרויקטים, שלבים

דוגמה קטנה אבל מלאה:

```json
{
 "updated": "2026-11-12",
 "focus": "website",
 "groups": ["עבודה", "לימודים", "בית"],
 "projects": [
  {
   "id": "website",
   "name": "אתר הסטודיו",
   "group": "עבודה",
   "status": "work",
   "about": "אתר חדש לסטודיו: עיצוב, בנייה, פרסום.",
   "link": "https://example.com",
   "stages": ["עיצוב", "בנייה", "תוכן", "פרסום"],
   "current": 1,
   "last_move": "2026-11-10"
  },
  {
   "id": "english",
   "name": "קורס אנגלית",
   "group": "לימודים",
   "status": "pause",
   "stages": ["A01–A08: יסודות", "A09–A16: שיחה", "A17–A24: כתיבה"],
   "current": 0,
   "last_move": "2026-10-20"
  }
 ],
 "history": [
  {"date": "2026-11-10", "project": "website", "text": "העיצוב אושר"}
 ]
}
```

שדות הקובץ:

| שדה | משמעות |
|---|---|
| `updated` | תאריך העדכון הידני האחרון (מוצג מתחת לכותרת) |
| `focus` | ה-id של הפרויקט שמוצג בכרטיס **מיקוד** בתפריט; ריק: הפרויקט הראשון שבעבודה |
| `groups` | הקבוצות בסדר התפריט; לכל קבוצה פריט תפריט משלה |
| `projects` | הפרויקטים (בהמשך) |
| `history` | אירועים, החדשים למעלה: `date`, `project` (id), `text` |
| `ideas_files` | קובצי רעיונות ([סעיף 5](#5-רעיונות)) |
| `reports_dir`, `monthly_reports_dir` | תיקיות הדוחות ([סעיף 7](#7-דוחות-מחקרים-וסיכומים)) |
| `digest_repo` | תיקיית מאגר הסיכומים ([סעיף 7](#7-דוחות-מחקרים-וסיכומים)) |

שדות של פרויקט:

| שדה | משמעות |
|---|---|
| `id` | מזהה קצר באותיות לטיניות, ייחודי: `website`, `english` |
| `name` | השם שמוצג בחלון |
| `group` | אחת מ-`groups` |
| `status` | `work` (בעבודה), `pause` (בהשהיה), `stop` (נעצר), `plan` (מתוכנן); גם המילים ברוסית `в работе`, `на паузе`, `остановлен`, `план` עובדות |
| `about` | משפט או שניים על הפרויקט (לא חובה) |
| `link` | קישור בכרטיס הפרויקט, למשל ללוח שלו (לא חובה) |
| `stages` | שמות השלבים לפי הסדר |
| `current` | מספר השלב שבעבודה, **סופרים מ-0**; כל השלבים שלפניו הושלמו |
| `last_move` | התאריך שבו השלב השתנה לאחרונה (ממנו ההתראות סופרות ימים) |
| `source` | מאיפה ההתקדמות מגיעה אוטומטית ([סעיף 4](#4-התקדמות-שמתעדכנת-מעצמה), לא חובה) |
| `moves_with` | לפרויקט של תוכנית כוללת: מזהי פרויקטים שהתנועה שלהם נחשבת לתנועה שלו (לא חובה) |

הערות:

- טעות ב-`projects.json` (למשל פסיק חסר) לא שוברת את החלון: במקום הפרויקטים יוצג טקסט השגיאה.
- קבוצה ששמה בדיוק `Развитие` היא אזור ההתפתחות האישית: לפרויקטים שלה פריט תפריט משלהם, והם לא נכללים ב«כל הפרויקטים».
- התראות: פרויקט בעבודה בלי תנועה יותר מ-14 ימים, פרויקט בהשהיה יותר מ-30 ימים, פרויקט שנעצר. פרויקטים בסטטוס `plan` לא מעוררים התראות.

## 4. התקדמות שמתעדכנת מעצמה

בלי `source`, פרויקט זז כשאתם (או העוזר) משנים את `current` ואת `last_move`. עם `source`, הכפתור **לסנכרן נתונים** (וגם הפעלת התוכנה) קורא את ההתקדמות בשבילכם. הסנכרון אף פעם לא משנה את `projects.json`: הוא כותב את התוצאה ל-`auto.json`, והחלון מצרף את השניים. אם לפי המקור השלב נמוך מזה שכתבתם ביד, השלב שלכם נשאר ומופיעה אזהרה.

כל המקורות מקבלים `"since": "YYYY-MM-DD"`: אירועים מלפני התאריך הזה לא נוספים (שימושי אם ההיסטוריה עד אז כבר כתובה ביד).

**קובץ התקדמות** (לכל פרויקט, בלי git):

```json
"source": {"kind": "progress", "path": "C:\\Users\\<you>\\Projects\\Garden\\PROGRESS.json", "since": "2026-11-01"}
```

`PROGRESS.json` בתיקיית הפרויקט:

```json
{
 "stages": ["תכנון", "קנייה", "שתילה", "קטיף"],
 "current": 2,
 "stage_changed": "2026-11-08",
 "now": "שותלים את הערוגות בצד הדרומי",
 "events": [{"date": "2026-11-08", "text": "השתילים נקנו"}]
}
```

`stages` חייבים להיות זהים בדיוק לשלבי הפרויקט ב-`projects.json`. אירוע «Урок 06 пройден» נספר בסטטיסטיקה כשיעור.

**שלבים ממאגר git** (`kind: stages`): שמות השלבים ב-`projects.json` מתחילים במזהה ונקודתיים, למשל `G1: data model`, `G2: import`. ענף ששמו מכיל `stage-g2` אומר ששלב G2 התחיל; המיזוג שלו לענף הראשי אומר ש-G2 הושלם. שדות לא חובה: `file` (קובץ שלבים במאגר, `{"stages": [{"id": "g1", "date": "…", "merge_commit": "…"}]}`), `branch_pattern` (ביטוי רגולרי משלכם למזהה השלב בשמות ענפים), `"fetch": false` (לא להוריד מהשרת, לקרוא רק מה שכבר במחשב).

```json
"source": {"kind": "stages", "repo": "C:\\Users\\<you>\\GitHub\\my-app", "since": "2026-11-01"}
```

**שיעורים ממאגר git** (`kind: lessons`), לקורסים: שמות השלבים מתחילים בגוש של קודי שיעורים, למשל `A01–A08: יסודות`. commit שההודעה שלו מכילה קוד שיעור (`A05`) מעביר את הקורס לגוש הזה; commit «A01-A08 summary» (או «Итог модуля A01–A08») סוגר את הגוש.

**הסנכרון** מריץ `git fetch` (לא נוגע בקבצי העבודה), קורא את המקורות, וגם סופר commits ליום בכל המאגרים שבתיקיות שבהן נמצאים מאגרי הפרויקטים שלכם (רק מספרים, לסטטיסטיקה). בעיות מוצגות בחלון; השגיאה האחרונה נכתבת גם ל-`sync-last-error.txt`. אם אין גישה ל-GitHub, הסנכרון משתמש במה שכבר נמצא במחשב ומציין זאת.

## 5. רעיונות

הרעיונות נמצאים בקובצי Markdown. רושמים אותם ב-`projects.json`; כל קובץ הופך לתת-אזור של **רעיונות**:

```json
"ideas_files": [
 {"id": "main", "title": "רעיונות", "about": "כל מה שעולה בראש", "path": "C:\\Users\\<you>\\Notes\\IDEAS.md"}
]
```

בקובץ יש טבלת סיכום ופסקה לכל רעיון:

```markdown
| ID | Date | Idea | Status |
|---|---|---|---|
| A-1 | 2026-11-01 | ניוזלטר ללקוחות | идея |
| A-2 | 2026-11-05 | להעביר את האתר לאחסון חדש | в дорожной карте |

## A-1. ניוזלטר חודשי ללקוחות
- **Суть:** מכתב אחד בחודש עם חדשות והצעות.
- **Статус:** идея
```

מזהה רעיון הוא אות לטינית גדולה, מקף ומספר (`A-1`, `B-12`). מזהים של רעיונות אחרים בטקסט (`ראו A-2`) הופכים לקישורים.

החלון ממיין רעיונות לפי המילים הראשונות של הסטטוס (כרגע הוא מזהה מילים ברוסית):

| הסטטוס מתחיל ב- | משמעות |
|---|---|
| `сделано` | בוצע |
| `в дорожной карте` | במפת הדרכים |
| `решение` | החלטה שעוד לא בוצעה |
| מכיל `исследовать` | לחקור |
| `отказ` | ירד מהפרק |
| `ждёт`, `отложено` | ממתין |
| כל דבר אחר | רעיון |

התוכנה רק קוראת את קובצי הרעיונות. את היסטוריית שינויי הסטטוס היא שומרת בעצמה ב-`ideas-history.json`. האזור **שירותים** מציג רעיונות שסימנתם כשירותים (כפתור הדגל ליד רעיון; נשמר ב-`flags.json`).

למתקדמים: במקום קבצים, `ideas_db` יכול להצביע על מאגר רעיונות SQLite; התוכנה פותחת אותו לקריאה בלבד. אילו תצוגות היא מצפה למצוא, ראו `read_ideas_db` ב-`XControlP.pyw`.

## 6. Google Calendar

לא חובה. XControlP קורא את היומנים שלכם ולעולם לא כותב בהם (הרשאה `calendar.readonly`).

1. ב-[Google Cloud Console](https://console.cloud.google.com/) יוצרים פרויקט, מפעילים את **Google Calendar API**, מגדירים את מסך ההסכמה של OAuth (אפשר להשאיר אותו במצב Testing ולהוסיף את עצמכם כמשתמשי בדיקה).
2. **Google Auth Platform → Clients → Create client**, סוג **Desktop app**, ואז **Download JSON**.
3. שומרים את הקובץ בשם `google-client.json` בתיקיית XControlP.
4. בחלון פותחים את **יומן** ולוחצים **כניסה ל־Google**. חלון דפדפן יבקש הרשאה; התשובה חוזרת לתוכנה במחשב הזה.

כמה חשבונות: **+ חשבון** באזור היומן. כל עוד אפליקציית Google במצב Testing, ההרשאה מחזיקה 7 ימים, ואחר כך הלוח יבקש להיכנס שוב. היומן מתעדכן בהפעלה, כל 30 דקות כשהחלון פתוח, ובכפתור הסנכרון.

אירוע שבשמו `לילה` (או `night`, `ночн`) ושמתחיל ב-00:00 מוצג כלילה שמתחיל ביום הקודם.

## 7. דוחות, מחקרים וסיכומים

**דוחות.** דוחות שבועיים הם קובצי Markdown בשם `Weekly report 1–7.11.2026.md` (או `Weekly report 28.10–3.11.2026.md`), חודשיים: `Monthly report 2026-11.md`. כברירת מחדל הם נקראים מ-`reports/weekly` ומ-`reports/monthly` בתיקיית XControlP; כדי לקרוא ממקום אחר, מגדירים `reports_dir` ו-`monthly_reports_dir` ב-`projects.json` (אם הוגדר רק `reports_dir` משלכם, הדוחות החודשיים נקראים מתיקייה `Monthly` לצידו). קובץ `.json` באותו שם יכול להחזיק את המספרים והגרפים של הדוח עבור החלון; הפורמט שלו נמצא [במדריך לעוזר](assistant.md#דוחות). אם תיקיית הדוחות נמצאת בתוך מאגר git, דוח שעוד לא נמצא ב-`origin/main` מסומן «לא נשלח», ויומיים אחרי סוף השבוע שלו הוא הופך להתראה.

**מחקרים.** `research/research.json` מונה את רשומות המחקר; הטקסטים שלהן הם קובצי `.md` באותה תיקייה. הפורמט נמצא [במדריך לעוזר](assistant.md#מחקרים).

**סיכומים (לא חובה).** סיכומי חדשות יומיים ממאגר git משלכם: מגדירים `digest_repo` ב-`projects.json` (או את משתנה הסביבה `PULT_DIGEST_REPO`). במאגר נמצאים `digests/YYYY/MM/YYYY-MM-DD.json`; הסימונים שלכם «מעניין» ו«שימושי» נכתבים ל-`marks/YYYY/MM/YYYY-MM-DD.json`, והתוכנה עושה להם commit ו-push בעצמה. בלי `digest_repo` האזור נשאר ריק ושום פקודת git לא רצה.

## 8. תרגום הנתונים שלכם

כותבים את הנתונים (שמות פרויקטים, שלבים, אירועים) בשפה אחת. הכיתובים של החלון עצמו כבר מתורגמים. כדי לראות את הנתונים גם בשפות האחרות של החלון, מוסיפים `translations.json`:

```json
{
 "en": {"Сайт студии": "Studio website"},
 "he": {"Сайт студии": "אתר הסטודיו"}
}
```

המפתח הוא הטקסט בדיוק כפי שנכתב בנתונים; טקסט בלי תרגום מוצג כפי שהוא.

השבוע בחלון מתחיל ביום ראשון.

## 9. עדכון XControlP

עם git: `git pull` בתיקייה. בלי git: מורידים את הגרסה החדשה ומחליפים את קובצי התוכנה (סעיף 2, «התוכנה»). קובצי הנתונים שלכם לא שייכים ל-XControlP, ובשתי הדרכים לא נוגעים בהם. קודם סוגרים את החלון.
