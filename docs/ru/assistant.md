# Работа с ИИ-ассистентом

XControlP задуман так, чтобы его вели разговором. Вы говорите ассистенту, что произошло или чего хотите; ассистент меняет файлы данных; окно через несколько секунд показывает результат. Подойдёт любой ассистент, который умеет читать и писать файлы на вашем компьютере, например Claude Code или приложение Claude для компьютера с подключённой папкой XControlP.

## 1. Подключить ассистента

- Дайте ему доступ к папке XControlP (и к папкам ваших проектов, если он должен их читать).
- Правила для ассистента лежат в [`AGENTS.md`](../../AGENTS.md) в корне папки. Claude Code читает их сам (через `CLAUDE.md`). Другим ассистентам добавьте одну строку в их инструкции, например в инструкции проекта Claude:

```
Ты ведёшь мой пульт XControlP в C:\Users\<вы>\XControlP. Перед любым изменением прочитай AGENTS.md в этой папке и следуй ему.
```

## 2. О чём можно просить

- «Добавь проект: ремонт кухни, группа Дом, этапы: план, заказ, установка; мы на плане.»
- «Дизайн сайта готов, переведи его на сборку.»
- «Спланируй завтра: урок английского, отчёт и этап сайта.»
- «Отметь урок английского сделанным, а отчёт перенеси на завтра.»
- «Закрой сегодняшний день: 7, сайт занял больше времени, чем думали.»
- «Разбери запрос.» (после того как вы нажали **Запросить сводку дня** или **Запросить предложения**)
- «Напиши отчёт за неделю.»
- «Добавь идею: ежемесячная рассылка для клиентов.»
- «Переведи названия новых проектов на английский и иврит.»

## 3. Какие файлы ассистент может менять

| Файл | Ассистент… |
|---|---|
| `projects.json`, `translations.json` | правит их, сначала сделав резервную копию |
| файлы идей (`ideas_files` в `projects.json`) | правит их |
| `day.db` | **никогда не открывает**; план дня меняет только через `day.py` |
| `answers/` | пишет ответы на запросы |
| `requests/` | только читает |
| `research/`, `reports/` (или ваши папки отчётов) | пишет записи и отчёты |
| `data.js`, `auto.json`, `day.json`, `calendar.json`, `settings.json`, `alerts.json`, `proposals.json`, `flags.json`, `ideas-history.json` | не меняет: их пишет программа |
| `google-client.json`, `google-token*.json` | никогда не читает, не копирует и не отправляет: это ваши ключи |

Перед изменением файла данных ассистент копирует его в папку резерва с датой, например `_backups/2026-11-12 до нового проекта/` (папки, начинающиеся с `_`, git не учитывает).

## 4. Проекты

Поля описаны в [Настройке, раздел 3](setup.md#3-projectsjson-группы-проекты-этапы). Когда проект продвинулся:

- `current` становится номером нового этапа (счёт с 0);
- `last_move` становится сегодняшней датой;
- наверх `history` добавляется событие: `{"date": "…", "project": "<id>", "text": "…"}`.

Проекты с `source` двигает синхронизация; вручную ассистент их не двигает.

После правки проверьте файл: `python XControlP.pyw --build`; `data.js` должен начинаться с `window.BOARD = {` (при ошибке в нём `BOARD_ERROR` и причина). Пока окно открыто, программа пересобирает `data.js` сама.

## 5. План дня

План дня хранится в `day.db`, и пишет его только программа. Ассистент пользуется `day.py`: он проверяет каждый запрос тем же кодом, что и программа, и кладёт его в `day-inbox/`. Программа применяет запрос примерно через 10 секунд, пока окно открыто, иначе — при следующем запуске, и пишет итог в `day-inbox/applied/<имя>.result.json`.

```
python day.py projects                                   проекты, их id и этапы
python day.py show [--day 2026-11-12]                    план дня и запросы, которые ещё ждут
python day.py add --day D --project english --amount "1 урок" [--priority high|normal|low] [--note ТЕКСТ]
python day.py add --day D --project website --stage [N]   завершить этап N (номер как в окне, с 1)
python day.py add --day D --task "Позвонить в банк" [--project ID]
python day.py plan --day D --file plan.json [--replace]  весь день из списка задач JSON
python day.py status ID done|partial|not_done|active|planned|removed [--note ТЕКСТ]
python day.py note ID ТЕКСТ    priority ID high|normal|low    carry ID [--to D]    restore ID
python day.py edit ID [--stage N] [--amount ТЕКСТ] [--title ТЕКСТ]
python day.py order --day D ID ID ID …                   новый порядок всех задач дня
python day.py day-note --day D ТЕКСТ                     заметка дня
python day.py close --day D --rating 1..10 [--note ТЕКСТ] закрыть день
python day.py reopen --day D    carry-open --day D       открыть день снова · все незаконченные — на следующий день
python day.py result [ИМЯ]                               итог запроса
```

Номер задачи (ID) — 32 знака, его печатают `add` и `show`. День по умолчанию — сегодня по часам этого компьютера.

## 6. Запросы и ответы

Когда вы нажимаете **Запросить сводку дня** или **Запросить предложения**, программа пишет `requests/request-ГГГГ-ММ-ДД-ЧЧММСС-<вид>.json`:

```json
{"format": "pult-request", "id": "request-2026-11-12-173714-summary", "kind": "summary",
 "created": "2026-11-12T17:37", "lang": "ru",
 "snapshot": {"today": "…", "day_plan": [], "alerts": [], "projects": [], "week": {},
              "waiting_requests": [], "open_proposals": []}}
```

Когда вы пишете «разбери запрос», ассистент:

1. читает часы (время в ответе — только прочитанное, никогда не угаданное);
2. находит запрос без ответа (окно показывает его как ждущий);
3. разбирает снимок и, если нужно, файлы ваших проектов и отчёты;
4. пишет `answers/answer-<id запроса>.json`:

```json
{
 "format": "pult-answer", "version": 1,
 "request": "request-2026-11-12-173714-summary",
 "kind": "summary",
 "written": "2026-11-12T19:05",
 "original": "ru",
 "title":   {"ru": "Сводка дня", "en": "Day summary", "he": "סיכום היום"},
 "summary": {"ru": "…", "en": "…", "he": "…"},
 "blocks": [
  {"type": "points", "title": {"ru": "Сделано", "en": "Done", "he": "בוצע"},
   "items": [{"ru": "…", "en": "…", "he": "…"}]}
 ],
 "proposals": [
  {"id": "p1", "text": {"ru": "…", "en": "…", "he": "…"}, "why": {"ru": "…", "en": "…", "he": "…"}, "project": "website"}
 ]
}
```

- Каждый текст — объект с `ru`, `en` и `he`; все три обязательны.
- `kind` — `summary` или `proposals`; `summary`, `why` и `project` — по желанию; `id` предложения — латиница, цифры и дефис.
- Блоки — такие же, как в отчётах (ниже).

5. проверяет файл: `python tools/answer_check.py XControlP.pyw answers/<файл>` должен напечатать `OK`.

Испорченный ответ не теряется: окно показывает его с причиной.

## Отчёты

Отчёт — файл Markdown (`Weekly report 1–7.11.2026.md`, `Monthly report 2026-11.md`) в папке отчётов ([Настройка, раздел 7](setup.md#7-отчёты-исследования-и-сводки)). Файл данных с тем же именем и расширением `.json` позволяет окну его нарисовать:

```json
{
 "format": "pult-report", "version": 1, "original": "ru",
 "start": "2026-11-01", "end": "2026-11-07",
 "summary": {"ru": "…", "en": "…", "he": "…"},
 "rating": 8,
 "kpis": [{"id": "tasks", "value": 23}, {"id": "done_pct", "value": 74}],
 "categories": [
  {"id": "summary", "title": {"ru": "Итог", "en": "Summary", "he": "סיכום"}, "blocks": []},
  {"id": "risks", "title": {"ru": "Риски", "en": "Risks", "he": "סיכונים"}, "blocks": []}
 ]
}
```

- id показателей `kpis`: `commits`, `repos`, `tasks`, `done_pct`, `day_rating`, `lessons`, `ideas_new`, `hq_rating`. Окно сравнивает их с прошлым отчётом.
- id категорий со своим значком: `summary`, `tech`, `study`, `services`, `day`, `code`, `ideas`, `resources`, `decisions`, `risks`, `proposals`, `rating`; любой другой id тоже работает, без значка. У пунктов в `risks` и `proposals` есть кнопка **В план дня**.

Блоки (`T` — текст-объект с `ru`, `en`, `he`; заголовок по желанию, если не указано иное):

| Блок | Поля |
|---|---|
| `text` | `text: T` |
| `points` | `items: [T, …]` |
| `list` | `items: [{"title": T, "text": T}, …]` (нумерованный) |
| `table` | `columns: [T, …]`, `rows: [[ячейка, …], …]`, по желанию `total: [ячейка, …]`; ячейка — число или `T` |
| `bar` | `title: T`, `items: [{"label": T, "value": число}, …]`, по желанию `unit`, `note` |
| `line` | `title: T`, `items: [{"label": T, "value": число}, …]` |
| `stack` | `title: T`, `keys: [{"label": T}, …]`, `items: [{"label": T, "values": [число, …]}, …]` |
| `quotes` | `items: [{"date": "…", "topic": T, "text": T, "verbatim": true}, …]` |

## Исследования

`research/research.json`:

```json
{
 "research": [
  {
   "id": "market-2026-11", "date": "2026-11-12", "kind": "market", "original": "ru",
   "title": {"ru": "…", "en": "…", "he": "…"},
   "text": {"ru": "market-2026-11-ru.md", "en": "market-2026-11-en.md", "he": "market-2026-11-he.md"},
   "sources": [{"lang": "ru", "file": "market-2026-11-notes.md", "name": {"ru": "Заметки", "en": "Notes", "he": "הערות"}}],
   "services": ["A-1"]
  }
 ]
}
```

Файлы `.md` лежат в `research/` рядом с `research.json`. `services` связывает исследование с идеями, отмеченными как услуги.

## 9. Идеи и переводы

- Идеи: добавьте строку в сводную таблицу и раздел `## A-3. Название` в файле идей ([Настройка, раздел 5](setup.md#5-идеи)). Статус меняйте в обоих местах.
- Переводы: для каждого нового текста данных (название проекта, этап, событие, группа) добавьте английскую и ивритскую версии в `translations.json` (ключ — текст ровно так, как он написан).

Каждое изменение ассистент заканчивает одной строкой: что изменил и где.
