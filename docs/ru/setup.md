## 1. Установка и первый запуск

1. Установите Python 3.10 или новее с [python.org](https://www.python.org/downloads/) (оставьте галочку установки запускателя `py`).
2. Положите XControlP в свою папку, например `C:\Users\<вы>\XControlP` (`git clone` или **Download ZIP**).
3. Дважды щёлкните `create_shortcut.pyw`: он создаёт на рабочем столе ярлык **XControlP**. Если не получилось, причина будет в `shortcut-error.txt`.
4. Откройте ярлык.

Что происходит при запуске:

- Если `projects.json` нет, он создаётся из `templates/projects.example.json` (пустой пульт). Существующий `projects.json` никогда не перезаписывается.
- Программа собирает из ваших файлов `data.js` (его читает окно) и запускает маленький веб-сервер, доступный только этому компьютеру (`127.0.0.1`). Запросы принимаются только от окна пульта — по ключу, который выдаётся при запуске.
- Окно открывается как окно-приложение Edge. Программа закрывается сама примерно через 10 минут после того, как окно закрыто.
- Один раз проходит синхронизация (см. [раздел 4](#4-продвижение-которое-обновляется-само)).

Пока окно открыто, программа пересобирает `data.js`, как только меняется `projects.json` или другой файл данных, а окно перечитывает его каждые 20 секунд. После правки ничего перезапускать не нужно.

Собрать `data.js`, не открывая окно: `python XControlP.pyw --build`.

| Файл | Что это |

| `XControlP.html`, `i18n.js` | окно и его надписи на английском и иврите |
| `collect.py` | синхронизация: читает продвижение из репозиториев и файлов продвижения |
| `day_store.py`, `day.py`, `day_test.py` | план дня: хранилище, инструмент командной строки для ассистента, тесты |
| `calendar_google.py` | вход в Google Календарь и чтение событий |
| `digest_store.py` | ежедневные сводки (по желанию) |
| `create_shortcut.pyw`, `start_fallback.cmd` | ярлык на рабочем столе, запасной запуск |
| `icons/`, `icon.ico`, `icon.svg` | значки |
| `templates/projects.example.json` | пустой начальный `projects.json` |
| `tools/answer_check.py` | проверяет файл ответа ассистента, прежде чем он попадёт в `answers/` |

**Ваши данные** (появляются по ходу работы; все — в `.gitignore`):

| Файл или папка | Что хранит | Кто пишет |
|---|---|---|
| `projects.json` | группы, проекты, этапы, история, настройки источников | вы или ассистент |
| `translations.json` | английские и ивритские версии текстов ваших данных | вы или ассистент |

| `research/` | записи исследований и их тексты | ассистент |
| `reports/` | недельные и месячные отчёты (если держать их здесь) | ассистент |
| `settings.json`, `alerts.json`, `flags.json`, `ideas-history.json` | настройки окна, отметки тревог, услуги, история идей | программа |

## 3. projects.json: группы, проекты, этапы

Небольшой, но полный пример:

```json
{
 "updated": "2026-11-12",
 "focus": "website",
 "groups": ["Работа", "Учёба", "Дом"],
 "projects": [
  {
   "id": "website",
   "name": "Сайт студии",
   "group": "Работа",
   "status": "в работе",
   "about": "Новый сайт студии: дизайн, сборка, публикация.",
   "link": "https://example.com",
   "stages": ["Дизайн", "Сборка", "Тексты", "Публикация"],
   "current": 1,
   "last_move": "2026-11-10"
  },
  {
   "id": "english",
   "name": "Курс английского",
   "group": "Учёба",
   "status": "на паузе",
   "stages": ["A01–A08: основы", "A09–A16: разговор", "A17–A24: письмо"],
   "current": 0,
   "last_move": "2026-10-20"
  }
 ],
 "history": [
  {"date": "2026-11-10", "project": "website", "text": "Дизайн утверждён"}
 ]
}
```

Поля файла:

| Поле | Значение |
|---|---|
| `updated` | дата вашего последнего ручного обновления (видна под заголовком) |
| `focus` | id проекта для карточки **ФОКУС** в меню; пусто — первый проект в работе |
| `groups` | группы в порядке меню; у каждой группы свой пункт меню |
| `projects` | проекты (ниже) |
| `history` | события, новые сверху: `date`, `project` (id), `text` |
| `ideas_files` | файлы идей ([раздел 5](#5-идеи)) |
| `reports_dir`, `monthly_reports_dir` | папки отчётов ([раздел 7](#7-отчёты-исследования-и-сводки)) |
| `digest_repo` | папка репозитория сводок ([раздел 7](#7-отчёты-исследования-и-сводки)) |

Поля проекта:

| Поле | Значение |
|---|---|
| `id` | короткий латинский id, уникальный: `website`, `english` |
| `name` | название в окне |
| `group` | одна из `groups` |
| `status` | `в работе`, `на паузе`, `остановлен`, `план`; английские `work`, `pause`, `stop`, `plan` тоже подходят |
| `about` | одно-два предложения о проекте (по желанию) |
| `link` | ссылка на карточке проекта, например на его доску (по желанию) |
| `stages` | названия этапов по порядку |
| `current` | номер этапа в работе, **считая с 0**; все этапы до него пройдены |
| `last_move` | дата последней смены этапа (от неё тревоги считают дни) |
| `source` | откуда продвижение берётся само ([раздел 4](#4-продвижение-которое-обновляется-само), по желанию) |
| `moves_with` | для проекта-общего плана: id проектов, чьё движение считается его движением (по желанию) |

Заметки:

- Ошибка в `projects.json` (например, пропущенная запятая) не ломает окно: вместо проектов оно покажет текст ошибки.
- Группа с названием ровно `Развитие` — раздел личного развития: у её проектов свой пункт меню, и они не входят в «Все проекты».
- Тревоги: проект в работе без движения больше 14 дней, проект на паузе больше 30 дней, остановленный проект. Проекты со статусом `план` тревог не поднимают.

## 4. Продвижение, которое обновляется само

Без `source` проект двигается, когда вы (или ассистент) меняете `current` и `last_move`. С `source` продвижение за вас читает кнопка **Синхронизировать данные** (и запуск программы). Синхронизация никогда не меняет `projects.json`: она пишет итог в `auto.json`, а окно складывает одно с другим. Если по источнику этап меньше записанного вручную, остаётся ваш, а в окне появляется предупреждение.

Все источники понимают `"since": "ГГГГ-ММ-ДД"`: события раньше этой даты не добавляются (удобно, если история до неё уже записана вручную).

**Файл продвижения** (для любого проекта, git не нужен):

```json
"source": {"kind": "progress", "path": "C:\\Users\\<вы>\\Projects\\Garden\\PROGRESS.json", "since": "2026-11-01"}
```

`PROGRESS.json` в папке проекта:

```json
{
 "stages": ["План", "Покупка", "Посадка", "Урожай"],
 "current": 2,
 "stage_changed": "2026-11-08",
 "now": "Сажаем грядки с южной стороны",
 "events": [{"date": "2026-11-08", "text": "Саженцы куплены"}]
}
```

`stages` должны точно совпадать с этапами проекта в `projects.json`. Событие «Урок 06 пройден» засчитывается в статистике как урок.

**Этапы из репозитория git** (`kind: stages`): названия этапов в `projects.json` начинаются с id и двоеточия, например `G1: модель данных`, `G2: импорт`. Ветка, в имени которой есть `stage-g2`, означает, что этап G2 начат; её слияние в основную ветку — что G2 пройден. Необязательные поля: `file` (файл этапов в репозитории, `{"stages": [{"id": "g1", "date": "…", "merge_commit": "…"}]}`), `branch_pattern` (своё регулярное выражение для id этапа в именах веток), `"fetch": false` (не забирать с сервера, читать только то, что есть на компьютере).

```json
"source": {"kind": "stages", "repo": "C:\\Users\\<вы>\\GitHub\\my-app", "since": "2026-11-01"}
```

**Уроки из репозитория git** (`kind: lessons`), для курсов: названия этапов начинаются с блока кодов уроков, например `A01–A08: основы`. Коммит, в сообщении которого есть код урока (`A05`), переводит курс в этот блок; коммит «Итог модуля A01–A08» (или «A01-A08 summary») закрывает блок.

**Синхронизация** делает `git fetch` (рабочие файлы не трогает), читает источники и считает коммиты по дням во всех репозиториях тех папок, где лежат репозитории ваших проектов (только числа, для статистики). Проблемы видны в окне; последняя ошибка ещё и пишется в `sync-last-error.txt`. Если GitHub недоступен, используется то, что уже есть на компьютере, и окно об этом говорит.

## 5. Идеи

Идеи живут в файлах Markdown. Перечислите их в `projects.json`; каждый файл — подраздел раздела **Идеи**:

```json
"ideas_files": [
 {"id": "main", "title": "Идеи", "about": "Всё, что приходит в голову", "path": "C:\\Users\\<вы>\\Notes\\IDEAS.md"}
]
```

В файле — сводная таблица и раздел на каждую идею:

```markdown
| № | Дата | Идея | Статус |
|---|---|---|---|
| A-1 | 2026-11-01 | Рассылка для клиентов | идея |
| A-2 | 2026-11-05 | Перенести сайт на новый хостинг | в дорожной карте |

## A-1. Ежемесячная рассылка для клиентов
- **Суть:** одно письмо в месяц с новостями и предложениями.
- **Статус:** идея
```

Номер идеи — заглавная латинская буква, дефис и число (`A-1`, `B-12`). Номера других идей в тексте (`см. A-2`) становятся ссылками.

Окно сортирует идеи по первым словам статуса:

| Статус начинается с | Значение |
|---|---|
| `сделано` | сделано |
| `в дорожной карте` | в дорожной карте |
| `решение` | решение, ещё не выполненное |
| содержит `исследовать` | исследовать |
| `отказ` | отказ |
| `ждёт`, `отложено` | ждёт |
| что-то другое | идея |

Файлы идей программа только читает. Свою историю смены статусов она ведёт в `ideas-history.json`. Раздел **Услуги** показывает идеи, которые вы отметили как услуги (кнопка-флажок у идеи; хранится в `flags.json`).

Для продвинутых: вместо файлов `ideas_db` может указывать на базу идей SQLite; программа открывает её только для чтения. Какие представления она ждёт — см. `read_ideas_db` в `XControlP.pyw`.

## 6. Google Календарь

По желанию. XControlP читает ваши календари и никогда в них не пишет (разрешение `calendar.readonly`).

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект, включите **Google Calendar API**, настройте экран согласия OAuth (можно оставить в режиме Testing и добавить себя как тестового пользователя).
2. **Google Auth Platform → Clients → Create client**, тип **Desktop app**, затем **Download JSON**.
3. Сохраните файл как `google-client.json` в папке XControlP.
4. В окне откройте **Календарь** и нажмите **Войти в Google**. Окно браузера попросит разрешения; ответ вернётся программе на этом компьютере.

Несколько аккаунтов — кнопка **+ Аккаунт** в разделе «Календарь». Пока приложение Google в режиме Testing, разрешение живёт 7 дней, потом пульт попросит войти снова. Календарь обновляется при запуске, каждые 30 минут, пока окно открыто, и кнопкой синхронизации.

Событие, в названии которого есть `ночн` (или `night`, `לילה`) и которое начинается в 00:00, показывается как ночь с предыдущего дня.

## 7. Отчёты, исследования и сводки

**Отчёты.** Недельные отчёты — файлы Markdown с именами `Weekly report 1–7.11.2026.md` (или `Weekly report 28.10–3.11.2026.md`), месячные — `Monthly report 2026-11.md`. По умолчанию они читаются из `reports/weekly` и `reports/monthly` в папке XControlP; чтобы читать из другого места, задайте `reports_dir` и `monthly_reports_dir` в `projects.json` (если задан только свой `reports_dir`, месячные отчёты читаются из папки `Monthly` рядом с ним). Файл `.json` с тем же именем может хранить цифры и графики отчёта для окна; его формат — в [руководстве для ассистента](assistant.md#отчёты). Если папка отчётов лежит в репозитории git, отчёт, которого ещё нет в `origin/main`, помечается «не отправлен», а через два дня после конца его недели становится тревогой.

**Исследования.** `research/research.json` — список записей исследований; их тексты — файлы `.md` в той же папке. Формат — в [руководстве для ассистента](assistant.md#исследования).

**Сводки (по желанию).** Ежедневные сводки новостей из вашего репозитория git: задайте `digest_repo` в `projects.json` (или переменную окружения `PULT_DIGEST_REPO`). В репозитории лежат `digests/ГГГГ/ММ/ГГГГ-ММ-ДД.json`; ваши отметки «интересно» и «полезно» идут в `marks/ГГГГ/ММ/ГГГГ-ММ-ДД.json`, и программа сама их коммитит и отправляет. Без `digest_repo` раздел пуст и ни одна команда git не запускается.

## 8. Переводы ваших данных

Пишите данные (названия проектов, этапы, события) на одном языке. Надписи самого окна уже переведены. Чтобы видеть данные и на других языках окна, добавьте `translations.json`:

```json
{
 "en": {"Сайт студии": "Studio website"},
 "he": {"Сайт студии": "אתר הסטודיו"}
}
```

Ключ — текст ровно так, как он написан в данных; текст без перевода показывается как есть.

Неделя в окне начинается с воскресенья.

## 9. Обновление XControlP

С git: `git pull` в папке. Без git: скачайте новую версию и замените файлы программы (раздел 2, «Программа»). Ваши файлы данных не входят в XControlP и в обоих случаях не затрагиваются. Сначала закройте окно.

## 10. Если что-то не работает

| Что видно | Что делать |
|---|---|
| Окно открылось страницей без кнопки **Синхронизировать данные** | Локальный сервер не запустился (уже работает другая копия или его заблокировал брандмауэр). Закройте все окна XControlP, подождите минуту и откройте снова. |
| Текст ошибки вместо проектов | В `projects.json` ошибка; в тексте указана строка. |
| Проблема синхронизации в окне | Прочитайте пометку; последняя ошибка есть и в `sync-last-error.txt`. |
| Окно не открывается совсем | Запустите `start_fallback.cmd`; если нет Python — установите его (раздел 1). |
| Календарь просит войти снова | В режиме Testing у Google это нормально (раз в 7 дней). |
